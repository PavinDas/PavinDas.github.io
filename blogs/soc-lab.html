Section 01 // Blueprint

Introduction & Operational Workflow

In this guide, I’ll walk you through the process of creating a home lab for a Security Operations Center (SOC) using Oracle VirtualBox. The goal is to detect malicious activity, improve incident response, and automate actions to cut down response time and reduce manual work.

Environment Components & Workflow

  • Kali Linux: Attacker machine located outside the firewall.
  • Windows 10 Host: Client machine equipped with Microsoft Sysmon for granular endpoint telemetry.
  • Ubuntu Machine: Defense and server host within the internal subnet.
  • OPNsense Firewall: Gateway filtering traffic between bridged WAN and the internal network.
  • Wazuh (SIEM): Aggregates and correlates logs from network and endpoints.
  • Shuffle (SOAR): Receives webhooks on critical alerts to trigger automated containment and ticketing.
Automated Detection & Containment Cycle

1. Wazuh agents forward real-time logs to Wazuh Cloud.
2. Rule correlations detect malicious activity (e.g., brute-force attacks).
3. An alert triggers a webhook payload directly into Shuffle SOAR.
4. Shuffle checks cache to eliminate duplicate alerts and logs a Jira incident ticket.
5. The offending IP is automatically dispatched to OPNsense to block traffic.

Section 04 // Detection Logic

Configuring Custom Alerting Rules in Wazuh

In Wazuh → Alerting, create a custom monitor to detect repeated authentication failures:

  • Monitor Name: Failed Login Monitor
  • Type: Per query monitor (Frequency: 1 minute)
  • Index: wazuh-alerts
  • Query Filter: rule.id = 60122
  • Trigger Condition: Count IS ABOVE 5
